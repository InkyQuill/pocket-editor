# Архитектура Pocket Editor

## Границы системы

Pocket Editor — Android-приложение без собственного backend, аналитики и телеметрии. Yandex ID/OAuth и шлюз Yandex Disk REST API находятся на границе с внешним сервисом; все пользовательские локальные данные остаются в app-private storage.

## Источники истины и локальные данные

Канонический Markdown — read-only источник истины. Локальные данные включают кэш файлов книги и Room-метаданные, индекс поиска, ревизии и outbox. Точные sync bases (merge base) сохраняются, чтобы публикация не смешивала несопоставимые версии.

## Yandex Disk и удалённый корень

Выбранная папка представляется нормализованным идентификатором удалённого корня. Удалённый набор служит источником Markdown, манифеста и одного review sidecar на главу. Сетевой доступ идёт только через Yandex Disk REST API с OAuth-авторизацией.

## Хранение и фоновые задачи

Room хранит состояние книг, поиска, ревизий, очереди outbox и восстановления. WorkManager выполняет возобновляемые фоновые задачи. Временный sync lock координирует публикацию: владелец повторно проверяет nonce, а проигравший не выполняет защищённые записи.

## Форматы и протокол синхронизации

На удалённой стороне приложение создаёт и обновляет манифест, один review sidecar на главу и временный sync lock. Публикация защищена проверкой базы и явной передачей конфликта пользователю; канонический Markdown не публикуется приложением. Форматы описаны в `schemas/`.

## Прогрессивная установка и удаление книги

Обнаружение строит список глав и порог начальной готовности. Процесс: прогрессивная загрузка делает первые три главы читаемыми, затем последовательно догружает остальные, сохраняя прогресс для возобновления. Установка, восстановление и забывание книги сериализованы; mutation gates отвергают устаревшего publisher и не допускают resurrection удалённой локальной книги.

## Markdown, выделение и редакторский слой

Markdown рендерится локально. `source-byte mapping` фиксирует UTF-8 соответствие между отображаемым фрагментом и источником. Многоблочное выделение, устойчивые anchors и редакторские overlays поддерживают сигналы, комментарии, правки и заметки без изменения канонического текста.

## Инварианты мутаций и восстановление после сбоя

Защищённая удалённая публикация проходит проверку актуальной базы и владения блокировкой. Незавершённые задания и локальные черновики восстанавливаются, а конфликт никогда не разрешается молча. Координатор не разрешает старой работе вернуть на устройство уже забытую книгу.

## Безопасность и приватность

OAuth-токены и кэш находятся в защищённом пространстве приложения. В репозитории и журналах не хранятся токены, полные пути, рукописи или содержимое запросов. Сервисная часть отсутствует, поэтому данные не отправляются в дополнительную инфраструктуру Pocket Editor.

## Осознанные ограничения

Приложение не редактирует канонический Markdown и не поддерживает автоматическое разрешение неоднозначных привязок. Сетевая синхронизация требует валидированного подключения и авторизации; доступность Яндекс Диска зависит от внешнего сервиса.
