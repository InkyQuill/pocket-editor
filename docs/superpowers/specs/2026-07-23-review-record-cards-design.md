# Карточки существующих рецензий

## Цель

Переработать список существующих сигналов и правок в панели рецензий так, чтобы карточки были компактными, легко сканировались и позволяли перейти к привязанному месту без размещения постоянных кнопок действий.

## Внешний вид

- Каждая карточка занимает всю доступную ширину панели рецензий во всех режимах: телефонный sheet, портретный overlay и landscape sidebar.
- Слева карточки располагается вертикальная полоса шириной 4 dp.
- Для сигнала полоса использует цвет соответствующего `SignalType` из `LocalReviewColors`.
- Для правки полоса использует цвет `changeNeeded` из `LocalReviewColors`.
- Текстовая метка типа не показывается: тип обозначается только цветом полосы.
- Остальной фон, форма и обводка следуют текущей теме приложения.

## Содержимое

### Сигнал

1. Выбранный исходный фрагмент показывается первым:
   - стиль `bodySmall`;
   - цвет `onSurfaceVariant`;
   - максимум две строки;
   - переполнение завершается ellipsis.
2. Комментарий показывается ниже стилем `bodyMedium`, максимум четыре строки, переполнение завершается ellipsis.
3. Если комментарий пуст, нижний текстовый блок не создаётся.
4. Полный, неусечённый текст остаётся доступен через переход в редактирование (long-press → «Редактировать»), поэтому усечение в карточке не теряет данные для пользователя.

### Правка

1. Исходный текст `before` показывается как приглушённый двухстрочный фрагмент по тем же правилам.
2. Новый текст `after` показывается ниже стилем `bodyMedium`, максимум четыре строки, переполнение завершается ellipsis; полный текст доступен так же через редактирование.

## Взаимодействие

### Обычный тап

- Тап по карточке прокручивает текст главы к блоку, содержащему начало anchor рецензии.
- Если anchor отсутствует, тап ничего не меняет; перепривязка по-прежнему выполняется существующим отдельным действием для unresolved-записи.
- На телефоне и в портретном overlay панель рецензий закрывается после выбора, чтобы пользователь сразу увидел текст.
- В landscape sidebar панель остаётся открытой, поскольку она не перекрывает текст.

### Long-press

- Long-press открывает привязанное к карточке `DropdownMenu`.
- Меню содержит два пункта:
  - иконка редактирования и текст «Редактировать»;
  - иконка удаления и текст «Удалить».
- Выбор пункта сначала закрывает меню, затем вызывает существующий callback.
- Удаление сохраняет действующий undo-flow со snackbar.
- Старые постоянные кнопки редактирования и удаления из карточки удаляются.

## Архитектура

- `ReviewRecordCard` получает отдельно исходный фрагмент, основной текст, цвет маркера, anchor и callbacks перехода, редактирования и удаления.
- `ReviewShell` преобразует сигнал и правку в параметры карточки, не дублируя presentation-логику.
- Переход по карточке переиспользует существующий механизм `ReaderSearchTarget` (`ReaderScreen.kt`: `targetBlockIndex` сопоставляет `rawStartByte` с `ReaderDocument.blocks.rawRange`, затем `listState.scrollToItem`), а не отдельное параллельное состояние: тап по карточке формирует `ReaderSearchTarget` из `anchor.startByte` и передаёт его тем же путём, что и переход по результату поиска.
- Закрытие overlay зависит от текущего `ReaderLayoutMode`; фоновые данные рецензии и контроллер не меняются.

## Доступность

- Вся карточка имеет click и long-click semantics.
- Click-semantics карточки включают `contentDescription`, называющий тип записи (например, через существующий `signal.type.labelResource` или строку «Правка»): цветовая полоска — единственный видимый индикатор типа, поэтому незрячим и слабо различающим цвет пользователям тип должен быть доступен через semantics, а не только визуально.
- Long-click получает доступное описание действий с рецензией.
- Пункты меню имеют текст, иконки с декоративным `contentDescription = null` и стандартную минимальную touch-target область Material.
- Цвет остаётся единственным *видимым* обозначением типа по явному продуктовому решению; для accessibility тип дублируется в semantics, как описано выше.

## Проверка

- Instrumentation-тест подтверждает, что карточка занимает ширину контейнера.
- Проверяются порядок исходного и основного текста, четырёхстрочный ellipsis основного текста и двухстрочный ellipsis исходного.
- Проверяется, что click-semantics карточки содержат тип записи.
- Проверяется отсутствие старых inline-кнопок.
- Обычный тап прокручивает reader к anchor и закрывает только перекрывающую текст панель.
- Long-press показывает оба пункта меню; каждый вызывает правильный callback.
- Сценарии выполняются для phone, tablet portrait и tablet landscape fixtures.
- Полный JVM-набор, Android lint и instrumentation-набор должны завершаться без новых падений.
