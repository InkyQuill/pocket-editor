# Источники книг и Open Edda

## Выбор источника

Книга привязана к цепочке **провайдер → аккаунт → контейнер, если он есть → расположение**. У Edda контейнер — проект; у будущего адаптера Seafile — библиотека. У файловых облаков выбор папки может идти сразу после аккаунта. Один аккаунт обслуживает несколько независимых книг.

Реализованы Яндекс Диск и Open Edda. Seafile — следующий адаптер; Dropbox, OneDrive, Box и Google Drive — запланированные провайдеры. Они перечислены в каталоге возможностей, но не показываются как работающие подключения. Добавление провайдера требует адаптера `BookGateway` и его шагов авторизации/выбора; маршрутизация не зависит от глобально выбранного аккаунта.

Существующие Яндекс-книги сохраняют свои пути, идентификаторы, кэш и авторизацию. Яндекс пока использует существующий текущий аккаунт. Edda поддерживает несколько сохранённых аккаунтов и серверов.

## Подключение Edda

1. В библиотеке нажмите «Добавить книгу» и выберите Open Edda.
2. Выберите сохранённый аккаунт или добавьте сервер, почту и пароль. Рабочий сервер должен использовать HTTPS.
3. Выберите файловый проект, затем папку с главами Markdown. Можно выбрать корень проекта.
4. Для следующей книги повторите выбор; тот же проект может содержать `book-01/`, `book-02/` и другие независимые папки.

Аккаунты можно переподключать и отключать в выборе источника. Выход удаляет токен, сохраняя книги и их привязки. Пароль не сохраняется. Токен зашифрован Android Keystore; он отправляется только соответствующему серверу, без переходов по перенаправлениям.

## Идентичность и офлайн-работа

Привязка Edda включает нормализованный адрес сервера, ID авторизованного автора, ID проекта и относительный путь папки. Для копий одного манифеста в разных расположениях создаются отдельные локальные ID кэша. Исходные `book_id`, ID глав и записей рецензии на сервере сохраняются. Соответствие локального и исходного ID хранится отдельно от рукописи и переживает перезапуск.

Первые главы загружаются существующим прогрессивным загрузчиком. Чтение, рецензирование, очередь отправки, базовые версии слияния, конфликты и положение чтения принадлежат отдельной книге. Исходный Markdown остаётся read-only. Приложение публикует только манифест, рецензии и временную кооперативную блокировку. Неизвестные файлы проекта и соседние книги сохраняются.

## Синхронизация

Адаптер Edda читает дерево версии проекта и неизменяемые объекты, проверяет размер и SHA-256 скачанных данных. Каждая запись публикует новое дерево с `expectedVersion` и уникальным `operationId`. Изменение проекта с компьютера после чтения основы отклоняет устаревшую запись; следующий проход получает новую основу и использует существующее слияние рецензий. Потерянный сетевой ответ проверяется по ID той же операции.

Кооперативная блокировка отдельной книги также меняется через сравнение версии. Чужая блокировка не снимается автоматически. Удаление своей блокировки использует актуальное дерево, сохраняя поступившие изменения других файлов. Манифест публикуется атомарно, без многошаговой замены файлов, необходимой Яндекс-адаптеру.

Синхронизация не применяет предложенные правки к тексту. Неразрешённые и устаревшие привязки остаются в рецензии для явного разбора. Edda хранит эти sidecar-файлы; семантический интерфейс рецензирования в Edda относится к последующему P4.

## Проверка реального обмена

При запущенном отдельном Android-эмуляторе:

```sh
python3 scripts/edda-roundtrip.py \
  --edda-repo /path/to/open-edda \
  --galley-repo /path/to/galley-desk \
  --adb /path/to/android-sdk/platform-tools/adb \
  --serial emulator-5554
```

Скрипт поднимает временный настоящий сервер Edda на `127.0.0.1:4199`, создаёт синтетические проекты и использует только отдельное хранилище. Проверяет три книги с одинаковым исходным `book_id`, офлайн-заметку в Android, неизменность Markdown, сохранение сигналов/правок/anchors, затем `edda get` → производственные кодеки Galley Desk → `edda send` → получение комментария и порядка глав в Android. Без `--galley-repo` выполняется только Android/Edda-часть. GUI Galley Desk этим сценарием не проверяется.

Разрешение HTTP для localhost находится только в debug-ресурсе. Release сохраняет запрет незашифрованного трафика.
