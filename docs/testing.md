# Проверка Pocket Editor

## Уровни проверки

JVM-тесты, lint, debug/release assembly, компиляция Android-тестов, connected-тесты, скриншоты, реальный Yandex E2E, offline/restart, проверка следов удаления и подписанное обновление — разные уровни доказательств. Успех одного уровня не заменяет другой.

## Быстрый локальный набор

```bash
./gradlew test lint assembleDebug compileDebugAndroidTestKotlin
```

Перед изменениями релизной конфигурации дополнительно собирайте `./gradlew assembleRelease`; перед UI/хранилищем запускайте соответствующие focused tests.

## Инструментальные тесты на эмуляторе

Роли окружений различаются: инструментальный AVD служит для воспроизводимых connected-тестов без реальной авторизации, а авторизованный Yandex AVD — для реальных read-only/E2E сценариев. Это не постоянные serial numbers.

```bash
./gradlew connectedDebugAndroidTest
```

Opt-in скриншотные и minified-fixture случаи пропускаются намеренно только при отсутствии обязательной fixture; такой пропуск не является зелёным E2E-результатом.

## Визуальная и UX-проверка

Для изменения reader, выделения или интерфейса запустите focused connected-тесты и сделайте скриншот ключевого состояния. Проверяйте прогресс, содержимое, поиск, оформление, конфликт и пустые/ошибочные состояния на реальном размере экрана.

## Реальный Yandex Disk E2E

Реальные проверки выполняются только с отдельным авторизованным Yandex AVD или устройством и одноразовой удалённой fixture. Для синхронизации и хранилища нужны unit-тесты, connected persistence-тесты и реальные сервисные проверки. Приватную `aria` можно только читать; порядок глав и записи проверяются на disposable fixture. Полный протокол — в [Yandex E2E runbook](runbooks/yandex-e2e.md).

## Offline, перезапуск и удаление локальной копии

Проверьте чтение после отключения сети, восстановление после перезапуска и отсутствие residue после удаления локальной копии. После «Удалить с устройства» локальные счётчики должны вернуться к baseline, а orphan work и файлы отсутствовать; удалённые данные не изменяются.

## Подписанное обновление

Для изменений релиза выполните policy-тесты workflow, release assembly, проверку подписи, checksum и in-place установку `adb install -r`. Проверка подписанного обновления включает сохранение кэша, позиции, черновиков и авторизации; порядок — в [runbook релиза](runbooks/release.md).

## Что перезапускать после изменений

- Storage/sync: JVM, connected persistence и реальный service-check.
- Reader/selection/UI: focused connected-тесты и скриншот.
- Release-конфигурация: workflow-policy tests, release assembly, signing verification, checksum и in-place upgrade.

## Последний подтверждённый результат

На 2026-08-16 подтверждены 565 JVM тестов. Connected run завершил 225 тестов: 5 намеренных opt-in screenshot/minified skips и 0 ошибок. Реальная read-only загрузка `aria` завершила 52 главы. Удаление локальной копии вернуло локальные счётчики к baseline без orphan work или файлов.
